# JPEG and linear DNG export verification

```powershell
dotnet run --project tests/ExportFormatTests -c Release
python tests/ExportFormatTests/verify_artifacts.py
```

The C# suite links the actual standalone production writers. The Python verifier reads the last artifact directory, compares every DNG RGB16 sample with the installed, previously authenticated reference implementation 2.2.3 `spektrafilm_gui/linear_dng.py`, and independently decodes the files with tifffile, LibRaw/rawpy 0.26.1 and Pillow. Only the reference module's brand-string import is stubbed: the real branding import initializes Qt settings. Pixel encoding and colour-matrix functions are executed unchanged. The reference source SHA-256 is included in `independent-verification.json`.

Verified: 130 C# assertions; 95,550 exact RGB16 samples across ten DNG files; ten LibRaw raw-pixel matches and successful RGB16 postprocesses; twelve Pillow JPEG decodes with exact ICC bytes. Cases include every headroom boundary from 0 through 4 stops, values above 16 and `float.MaxValue`, negative RGB, ignored NaN alpha, rejection of nonfinite RGB, quality 60/92/100, invalid inputs, destination preservation and cancellation during streamed DNG output. These are synthetic artifacts; the tests do not start Capture One or touch photographs/session data.

## API and encoding

`SpektraExport.SaveJpegWithProfile(path, rgb48, token, profilePath, quality)` requires RGB48 already encoded in the selected RGB profile. It rounds each 16-bit sample to the nearest 8-bit code at the final JPEG boundary, then encodes with WIC at explicit quality 1–100. UI defaults/range are 92 and 60–100. Alpha-bearing input is rejected rather than silently discarded. Every profile must pass the same structural RGB validation as TIFF/PNG. ICC is attached without a WIC colour transform. The same input pixels encoded with four different ICC profiles decode to identical RGB arrays, demonstrating that embedding does not apply a hidden conversion. JPEG remains lossy; it is not claimed byte-identical to reference implementation/OpenImageIO, whose final integer conversion truncates instead of rounding. [Microsoft JPEG quality documentation](https://learn.microsoft.com/en-us/dotnet/api/system.windows.media.imaging.jpegbitmapencoder.qualitylevel?view=windowsdesktop-10.0).

`SpektraExport.SaveLinearDng(path, ReadOnlyMemory<float> linearBt2020Rgba, width, height, token)` requires an unbounded linear BT.2020 RGBA frame after full processing and crop. The buffer must remain unchanged until completion. Alpha is not represented in the three-channel LinearRaw output. It returns `LinearDngInfo(HeadroomStops, Peak, NegativeSamples, OverRangeSamples)`. Counts are RGB **samples**, not pixels. Nonfinite RGB rejects the write before publication; finite negatives count and clip to zero. Positive peak determines power-of-two scaling, up to 4 EV; values above 16 count and clip. Values from 0 through 16 remain recoverable within half a 16-bit code at the selected scaling. All-negative frames retain their actual negative peak in the report and use zero headroom stops.

The DNG is little-endian classic TIFF, one uncompressed full-frame RGB16 strip, PhotometricInterpretation 34892, DNGVersion 1.4 / backward 1.1. The BT.2020 XYZ-to-RGB matrix is stored as signed rationals at 1e-6 precision with D65 calibration, neutral white balance, zero black, 65535 white, and positive BaselineExposure equal to scaling stops. Required UniqueCameraModel identifies `Spektrafilm C1 rendered RGB (linear BT.2020)`; it does not claim an original camera or physical scanner. No camera Make/Model, source EXIF, CFA, transfer table or ICC is copied. Crop metadata describes the complete supplied frame. Writer allocation beyond the caller's source is one RGB16 row plus small metadata. It checks the classic-TIFF 32-bit offset limit. [Adobe DNG 1.7.1 specification, pp. 22, 25, 32–37](https://helpx.adobe.com/content/dam/help/en/camera-raw/digital-negative/jcr_content/root/content/flex/items/position/position-par/download_section_733958301/download-1/DNG_Spec_1_7_1_0.pdf).

Raw converters can apply their own tone/white-balance/default exposure policies, so successful LibRaw processing does not promise identical rendered appearance in every converter. Exact raw-pixel preservation, matrix tags and headroom restoration are tested separately. DNG mathematical encoding follows GPL-3.0 reference implementation (see THIRD-PARTY.md), with provenance in the source header.

Both writers use the existing atomic publication helper. DNG cancellation is checked during validation and each output row; JPEG cancellation is checked during RGB quantization and before/after the synchronous WIC encoder. WIC encoding itself cannot be interrupted, but a cancelled result is not published. Existing `Save`, `SaveWithProfile`, TIFF/PNG quantization and compression remain unchanged. The separate ExportColorTests suite verifies RGB16/alpha/ICC and old/default sRGB byte equivalence; ExportColorIntegrationTests verifies actual finishing, strength and crop placement before the DNG buffer.
